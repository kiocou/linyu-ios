# 失败路径收尾与剩余验收

本轮继续本地修改，没有构建、推送或真实水控调用。

## 本轮完成的代码

- 对照 Android MainViewModel.loadUseCode：成功但 data 为空时保留已有使用码，不把刚确认的新码清空。
- 修正 DataStore 测试替身的严格 decode：与生产解析器相同，success=false 抛业务错误。另在独立网络回归中直接测试生产 decode/decodeShell，避免只验证替身。
- 新增空响应、刷新业务失败、领取业务拒绝的回归用例；拒绝领取不应改变当前码，也不触发成功后的刷新。
- 开阀确认失败、蓝牙费率写入未确认文案改成 Android ShowerController/BleShowerController 原文，保留结果未知语义，不提示用户用账单判断水是否已开。

## 核对后不改的地方

原始审查文档称云端首次确认不等待，但当前 Android ShowerController 的循环每轮均 delay(700)，包括首次。因此 iOS 现有首次等待与当前 Android 源码一致，不按审查表误改。原始文档保持原样，本记录补充勘误。

2. 统一运行本地累计的全部 Swift 回归，再做 Xcode Archive；当前静态检查不能证明编译和运行通过。
3. 手机验证：个人资料/使用码加载与刷新、首次分享、背景与导航安全区、卡片移动隐藏重启恢复、通知更正。
4. 真实设备验证：旧设备蓝牙连接及关阀结算、多设备隔离、挤号恢复、已结束订单不复活。
