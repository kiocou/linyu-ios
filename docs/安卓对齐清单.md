# 安卓端 → iOS 对齐清单

> 基准：`yehu-imei/linyu`（Android 3.1.0，Kotlin + Compose）
> 本仓库：`yehu-imei/linyu-ios`（Swift + SwiftUI，iOS 16+，XcodeGen + GitHub Actions）
>
> 原则：**除系统能力边界外，一律照搬安卓的代码思路与文案**。
> 每条都注明对应的 Android 源文件，方便逐行比对。

---

## 二、系统能力边界（有意降级，不是没做）

| 项 | Android 做法 | iOS 只能这样 | 影响 |
|---|---|---|---|
| 后台用水监控 | 前台服务 `ShowerWatchService` 常驻轮询、超时自动关停 | 无前台服务；前台计时器 + 回前台 `reconcileOnResume` 对齐 | **App 被挂起/杀掉期间不会自动关阀**；回到前台会立刻补判断 |
| 常驻通知进度 | 通知栏每秒刷新计时 | 一条静态「使用中」通知 + 「结束用水」按钮 | 通知里看不到跳动的秒数 |
| 通知按钮直接关阀 | `PendingIntent` → 服务直接发请求 | 点按钮回前台再执行 | 多一步「打开 App」 |
| 桌面小组件 | `AppWidgetProvider` 三种尺寸 | WidgetKit（**暂不做**，按你的决定放到软件内完善之后） | — |
| 应用内更新 | 下载 APK + 调系统安装器 | 只做版本检测 + 更新日志 + 「看教程」跳 GitHub | 装包仍走侧载 |
| MAC 地址 | 蓝牙栈直接给 MAC | CoreBluetooth 只给 `CBPeripheral.identifier` | 改用「状态帧自报 MAC」+ manufacturerData 解析 |
| 系统「密码」自动填充 | Android Autofill | 需要 Associated Domains + AASA 文件 + 对应签名能力 | 目前只有应用内 Keychain 记住密码 |

## 四、构建 / 验证

- Windows 上**无法编译**（没有 Swift/Xcode）。所有编译验证走 GitHub Actions：
  `gh workflow run ios.yml --ref <branch>` → 产出 `LinYu-unsigned-ipa`（未签名，侧载签名安装）。
- CI 里先跑回归检查（`Tests/*.swift`），再 Archive：
  - 账单缓存（7 项）
  - 待对账复核（6 项）
  - 结算金额解析 + 活跃订单仓库（24 项）

## 五、2026-10-23 本轮界面对齐

- 背景默认透明度改为 100%，与 Android `BackgroundState.DEFAULT_OPACITY` 一致；已保存的用户设置保持原值。
- 背景滚动内容裁剪在安全区内，页面底色覆盖状态栏；保留预览不参与触摸的修复。
- 恢复默认提示按用户指定改为“这将移除当前页面的自定义背景”（此文案有意覆盖安卓现有长文案）。
- 恢复确认打开时，边缘返回优先关闭确认，不直接退出背景设置页。
- 日志导出按 Android `exportLogs` 思路优先使用文件末尾 500 行，无文件内容时回退内存；不再拼接重复历史，导出文件放临时目录。
- 修正 MQTT 的文档、注释和日志用词；本轮不改变用水协议或结算逻辑。
